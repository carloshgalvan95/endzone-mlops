# ADR-010: One-shot 2024 validation and 2025 test

Date: 2026-11-13

Status: Accepted

## Context

Issue 61. Every public win-probability number is from rolling-origin CV, seasons 2016 through 2023. The README names 2024 as validation and 2025 as the test, and those seasons are not scored by the CV commands.

The Phase 2 CV winner is already fixed: logistic on `pkg_core_inj_l2`, C = 0.1, max_iter = 1000, lookback = 10, seed = 42, 47 columns. CV 2016-2023 log loss 0.6330, n = 2191. This ADR does not reopen that choice.

ADR-005 still governs a future feature comparison on the CV window. It is not a license to pick a different model after seeing 2025. ADR-009 still names logistic `h2_full` as the `prod` recipe. This evaluation does not register or promote.

On the reference table the market has the lower log loss: 0.6120 versus 0.6377 for logistic `h2_full`. The market row here is a benchmark. This is not betting advice.

## Decision

The holdout runs once, after this command is on `main`:

```bash
python scripts/run_holdout.py
```

`make holdout` and `.\scripts\dev.ps1 holdout` call that script. The script takes no scoring flags. `--allow-overwrite` is not part of the preregistered run.

Fits, with no leakage from the scored season:

- 2024 validation: train on seasons strictly before 2024 (1999 through 2023). Evaluate `season == 2024`.
- 2025 test: train on seasons strictly before 2025 (1999 through 2024). Evaluate `season == 2025`.
- Pooled 2024-2025: concatenate the two out-of-sample prediction sets. Do not refit on the pool.

Comparison rows:

- Final selected model: logistic `pkg_core_inj_l2`, C = 0.1, 47 columns.
- Prior reference, the `prod` recipe under ADR-009: logistic `h2_full`, C = 1.0.
- Context: `elo`, `elo_mov`, and `baseline-home`.
- Benchmark: `market`, the no-vig closing moneyline. Not a candidate.

Logistic `pkg_core_inj_l2`, logistic `h2_full`, and the home prior are refit for each scored season on `season < S`. Elo, `elo_mov`, and the market stay pregame values for that game. A 2024 result can update Elo for a later 2024 game, because that result is already known. A 2025 result is not used for any 2024 or 2025 prediction. 2024 rows are not in the 2024 training set. 2025 rows are not in either training set.

Metrics, for 2024, for 2025, and for `pooled_2024_2025`:

- Log loss, Brier, ROC AUC, and accuracy.
- Calibration: ECE and 10 equal-count decile bins.
- Paired bootstrap log-loss difference versus logistic `h2_full` and versus the market. 1000 resamples, seed 42. The difference is model minus reference. A negative value favors the model.
- Market-information regression: `market_coef` and `model_coef`. Descriptive. Not a blend and not a publishing weight.

Published counts use the games where every row has a finite probability, so the models share one n inside a season. Training still uses every labeled game with `season < S`. A row whose `home_won` is not 0 or 1 is not scored.

The command writes `docs/experiments/reports/holdout_2024_2025.json` and `docs/experiments/reports/holdout_2024_2025.md`. Those files are not in the tree until that run. If the JSON already exists, the command exits before it reads the warehouse. The run is logged to MLflow experiment `nfl_pregame/holdout_2024_2025` through `activate_tracking_experiment`. Nothing is registered and no alias is set.

The result is published whether or not holdout log loss is worse than the CV log loss 0.6330. No model is selected after seeing 2025.

`python -m endzone.modeling.train --val-season` still refuses `pkg_core_inj_l2` and the other CV challengers. This command is the only path that scores that feature set on 2024 and 2025.

## Consequences

One warehouse run. A second look at 2025 does not change the recipe, the regularization, or the comparison rows. `prod` stays logistic `h2_full` until a separate promotion, which this command does not perform. `store_failures` stays off. The 0.003 threshold is not moved. The frozen JSON and markdown are the record of whatever the holdout shows.
